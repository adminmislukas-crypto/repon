# Tasks: mobile-auth-login — core-api-issued sessions and login for `usuario-mobile` / `proveedor-mobile`

Expands `proposal.md` (D1-D5, locked) and `design.md` (D-1 through D-7, D-4a, locked) into a chained, test-first checklist. Order and hard constraints below are `design.md`'s, not re-derived here.

**Hard ordering (from `design.md`, not re-opened):**
1. PR1 ships `packages/auth`'s wiring probe **only** (D-7) — no auth logic. Everything else in `@repon/auth` depends on PR1's 4 acceptance gates passing first.
2. Backend session routes/rate-limiter/suspension checks (PR2a-PR7b) build in parallel with PR1 — no dependency on it. Mobile login screens (PR9/PR10) depend on **both** the backend routes existing **and** PR1's wiring proof having landed.
3. PR9 and PR10 are independent of each other; each depends on `@repon/auth`'s real implementation (PR8a/PR8b, post-PR1).
4. **Jest/RNTL scaffolding decision**: bundled into PR1, not a separate PR0 — `design.md` D-7's 4th acceptance gate (RNTL render test) *requires* the test runner to exist before PR1 can be verified, so scaffolding cannot be deferred past it.
